# 授权策略与署名思想（License Strategy）

本文记录本项目的授权策略与署名设计思想，供后续维护者理解"为什么这样配许可证、署名是干什么的"。

## 一、署名是防身武器，不是追责工具

我（作者 k4m7v2pz）署名的目的，**不是主动追究别人的署名义务**——谁把代码或美术拿过去、把许可证删了再发布，我无所谓，不会去追责。

署名存在的唯一价值是**防反咬**：应对网络上无证据的"盗用 / 剽窃"指责（尤其是情绪化的倒打一耙）。我的立场是：

- 我不在乎署名本身，只是中国法律环境不允许放弃署名权（署名权是人身权，不可转让、不可放弃）。
- 我不设置任何使用限制，只要别把东西说成是自己做的、然后反咬我抄袭盗用剽窃即可。

## 二、核心立场：永不盈利、纯开源

本项目**永远不会发售、不会盈利**——极端反感 Steam 独立游戏那套商业化运作，就是热爱开源、热爱分享。

这个立场直接决定了授权策略的取向：

- 素材仓库里的 **Suno AI 音乐**（`audio/music/suno_ai/`）按 Suno 免费计划仅限个人非商业使用，**对本项目不是限制**——因为永远不会触发"商用"条件，这批音乐可安心保留。
- 代码的双许可 / 素材的 OWL BY-PL 都是**为开放而生**：别人拿去随便用、随便改，我无限制。
- 任何人拿到本项目都无需担心商用条款——它从来就不打算用来赚钱。

## 三、为什么选木兰（Mulan）

1. **中文优先**：木兰许可证以中英双语表述、中文版为准，我能直接读懂条款，不依赖翻译和律师。
2. **防专利**：木兰系列（PSL / OWL）都带专利许可条款，别人拿本项目代码去主张专利时会受制衡，这层保护是 MIT 这类协议给不了的。

## 四、许可证矩阵

| 仓库 | 内容 | 许可证 | 说明 |
|---|---|---|---|
| `rust-bevy-endless-corridor` | 游戏代码 | Mulan PSL v2 + Unlicense 双许可 | `Cargo.toml`: `MulanPSL-2.0 OR Unlicense` |
| `rust-bevy-narrative-path-craft` | 引擎（纯文档骨架） | Mulan PSL v2 + Unlicense 双许可 | 等引擎从 endless-corridor 抽离后再建 crate |
| `assets-endless-corridor` | 美术 / 音效 / 音频 / 字体 / 设计 | Mulan OWL BY-PL v1 | 素材强制保留署名（BY） |

- **代码走宽松双许可**：中文优先、可商用、无署名强制，任选其一即可。
- **素材走 OWL BY-PL**：必须保留署名与版权声明——这是"防反咬"证据链的一环。

> SPDX 说明：Mulan OWL 系列目前**尚未收录进 SPDX 官方列表**，故素材仓库没有标准 SPDX 短标识，以官方全名与链接作为许可引用。

## 五、署名怎么落地：低调、不打扰

**游戏内零署名**——不像 Unity / Easy Anti-Cheat 那样在启动画面或游戏内高调展示作者，而是：

- 游戏运行时**不显示任何作者 / 版权信息**。
- 署名只存在于**仓库与文件层面**：打开仓库、打开文件管理器才能看见。

落地载体：

- `CREDITS`（三个仓库均有）：版权署名，作者 k4m7v2pz + 授权依据。
- `LICENSE` / `UNLICENSE`：许可证全文。
- **源工程文件**（FL Studio `.flp`、Krita 源文件等创作中间态）：原创性铁证，必须长期保留。

## 六、证据链：怎么防"倒打一耙"

真正击穿"别人说你抄袭"的，是永远留在我手里的原始记录：

1. **git 提交历史** —— 仓库与首次提交时间戳，删不掉。
2. **源工程文件** —— 别人只有成品，拿不出中间态。
3. **原始 LICENSE + CREDITS** —— 发布当天就标注了作者是谁。

别人就算删掉许可证再发布，也抹不掉仓库里的原始记录；删许可的动作反而成为"篡改来源"的破绽。证据在即可，无需主动追责。
